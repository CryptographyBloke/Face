# Project writing rules / 项目文案规则

- Use direct, concise, affirmative language in UI copy, comments and documentation.
- Describe the action, feature, data source or current state. Delete repetitive boilerplate,
  rhetorical contrasts and generic disclaimers that add no operational information.
- Keep examples labeled as examples; keep scan counts, source timestamps, verification
  status, access requirements and actionable errors accurate and close to their context.
- Record pending work and test coverage once in the relevant engineering document.
- Preserve wallet authorization, permission checks, validation and privacy behavior when
  editing copy. Put detailed security procedures in `SECURITY.md`.
- Apply the same writing standard to Chinese and English.

页面、注释和文档直接说明功能、动作、来源与状态。删除空泛免责话术和重复的否定对照句。
技术边界用具体参数和当前状态表达；待办与验证结果集中记录。以后新增文案沿用此规则。
